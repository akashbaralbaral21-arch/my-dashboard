Numbers, Math & the input() Trap

Two kinds of numbers, four operators, and why your calculator just printed "23"

🎯 Today's only goal

Build a tip calculator: it asks for a bill amount and a tip percentage, then prints the tip and the total. To do that you need exactly three new ideas:

  • Numbers — the two kinds Python has (int and float)
  • Math operators — + - * / and parentheses
  • Conversion — turning the text from input() into real numbers

Same rule as Day 1: every snippet has a Load ▶ button. Run it, predict it, break it, fix it.

🔍 Key words first

int A whole number: 5, -3, 0. No decimal point, no quotes.
float A number with a decimal: 2.5, -0.75. Note: 3.0 is a float too — the .0 makes it one.
Operators + add, - subtract, * multiply, / divide. Parentheses ( ) control order, exactly like school math. One surprise: / always gives a float — 10 / 5 prints 2.0, not 2.
Conversion int("42") → the number 42. float("4.2") → the number 4.2. str(5) → the text "5". This is the bridge between Day 1 and today, because input() always returns text, even when the human types a number.

💡 Smallest working example

price = 10
quantity = 3
total = price * quantity
print("Total:", total)
Lines 1–2: two boxes holding ints. No quotes — quotes would make them text, and text cannot multiply.
Line 3: Python reads the boxes, multiplies 10 × 3, stores 30 in a new box called total.
Line 4: the comma in print joins things with a space: Total: 30

✋ Practice rounds

Round 1 — order of operations

print(2 + 3 * 4)
print((2 + 3) * 4)

Predict both answers before Run. Python follows school math: multiply before add, parentheses first.

Round 2 — the division surprise

print(7 / 2)
print(10 / 5)

Second line prints 2.0, not 2. Division always returns a float. Know this, expect this.

Round 3 — THE TRAP (the most important round today)

a = input("First number: ")
b = input("Second number: ")
print(a + b)

Put 2 and 3 in the INPUT box (one per line). Run it. You asked for 2 + 3… and got 23.

Why: input() returns text. "2" + "3" glues text together — that is what + means for strings. Your program never did math at all.

Round 4 — fix the trap with conversion

a = float(input("First number: "))
b = float(input("Second number: "))
print(a + b)

Read it from the inside out: input() gets text → float(...) turns it into a number → the box stores the number. Now + does real math: 5.0.

Why float and not int? Because a human might type 2.5. int("2.5") crashes; float("2") works fine. When in doubt about numbers from humans, use float().

Optional 2-minute exploration: // and %

print(7 // 2)
print(7 % 2)

// divides and throws away the decimal (floor division). % gives the remainder. That's all — you'll need them later for loops. Play for 2 minutes, then move on.

⚠️ The only 3 mistakes that bite today

1. Doing math on raw input(): a = input() then a + 1 crashes with TypeError — text plus number is not allowed. Wrap it: float(input(...)).
2. int() on decimal text: int("2.5") crashes with ValueError. If the text might contain a dot, use float().
3. Gluing numbers with + inside print: print("Total: " + total) crashes when total is a number. Use a comma: print("Total:", total) — or convert with str(total).

Deliberately trigger mistake #1 in the shell and read the red TypeError. Recognizing it in 2 seconds later will save you hours.

✅ Check your understanding

1. What kind of number is 5, and what kind is 5.0?

5 is an int (whole). 5.0 is a float — the decimal point decides, not the value.

2. Why did Round 3 print 23 instead of 5?

input() returns text. "2" + "3" concatenates strings into "23". No conversion meant no math happened.

3. How do you turn the text "42" into a number? And "4.2"?

int("42") for the first, float("4.2") for the second. int("4.2") would crash.

4. What does print(10 / 2) show, and why?

2.0 — division always returns a float in Python 3, even when it divides evenly.
